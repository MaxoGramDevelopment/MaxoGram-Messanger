# План реализации: Авторизация через Cloud Firestore в MaxoGram

Пользователь выбрал вариант хранения и авторизации аккаунтов напрямую в **Cloud Firestore** без привязки к провайдеру Email/Password Firebase Console, что решает ошибку `OPERATION_NOT_ALLOWED`.

---

## 1. Архитектура аутентификации в Cloud Firestore

- **Хранение пользователей**:
  - Коллекция `users` в Firestore с детерминированным или уникальным ID (`u_<username>`).
  - Поля: `userId`, `username`, `displayName`, `passwordHash` (хэш SHA-256 с солью), `status`, `createdAt`, `updatedAt`, `lastSeen`.
- **Регистрация**:
  - Проверка уникальности юзернейма в Firestore.
  - Сохранение документа пользователя с хэшированным паролем.
  - Сохранение локальной сессии для авто-входа.
- **Вход**:
  - Поиск пользователя по `@username`.
  - Проверка совпадения хэша пароля.
  - Запуск синхронизации диалогов и сообщений в реальном времени.
- **Сохранение сессии**:
  - Автоматическое запоминание авторизованного пользователя в SharedPreferences, чтобы не вводить логин и пароль при каждом перезапуске.

---

## 2. Обновление правил безопасности Firestore (`firestore.rules`)

- Адаптация правил `firestore.rules`:
  - Разрешить чтение и создание профилей пользователей с валидацией схемы (валидные имена, поля, хэш пароля).
  - Разрешить участникам чата создавать и читать сообщения в `chats` и `messages` как с Firebase Auth (Google Sign-In), так и по уникальному идентификатору пользователя MaxoGram.
- Деплой обновленных правил через `deploy_firebase`.

---

## 3. Обновление UI и логики

- **`FirebaseChatService.kt`**:
  - Реализация `register` и `login` через Firestore `users` с проверкой пароля.
  - Поддержка быстрого выхода (`logout`) и сохранения сессии.
  - Обработка ошибок (неверный пароль, пользователь не найден, юзернейм уже занят).
- **`AuthScreen.kt`**:
  - Четкие подсказки о том, что регистрация происходит прямо в облачной базе Google Cloud.
  - Сохранение возможности переключения на «Через Google» и «WebSocket сервер».

---

## 4. Верификация

1. Проверка компиляции проекта через `compile_applet`.
2. Запуск локальных JVM-тестов через `gradle :app:testDebugUnitTest`.
3. Деплой обновленных правил Firestore.
